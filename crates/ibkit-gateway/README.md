# ibkit gateway

Rust control for Interactive Brokers Gateway, as `ibkit gateway`. The project replaces IBAutomater's C# process manager and Java automation agent with a Rust command, library, and native JVM agent. Gateway and its bundled Java runtime remain required.

The crates live in the ibkit workspace: `ibkit-gateway-core` (configuration, events, dialog policy), `ibkit-gateway` (the controller library) and `ibkit-cli` (the `ibkit` command and, as its library, the native JVM agent). Run the commands below from the workspace root. There is no Java automation JAR and no .NET runtime. A small JVM Runnable class is generated by Rust at build time. It only enters the Java UI thread; all automation rules are Rust code.

This release implements the IBAutomater feature set. Account login, API access with an account, and daily or weekly token renewal still need account tests. They are not certified by the offline checks.

## Install

macOS and Linux (glibc; the agent loads into Gateway's JVM, which IBKR ships for glibc only):

```sh
curl -fsSL https://raw.githubusercontent.com/racetozero/ibkit/main/install.sh | sh
```

Windows x64 (experimental):

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://raw.githubusercontent.com/racetozero/ibkit/main/install.ps1 | iex"
```

The installers select the release for this machine, check its SHA-256 checksum, and install `ibkit` in `~/.local/bin` with its agent in `~/.local/lib` (on Windows, both in `~\.local\bin`). Set `IBKIT_VERSION` for a specific release and `IBKIT_INSTALL_DIR` for another directory. Update later with `ibkit update`, which replaces the binary and the agent together; restart running controllers afterwards, so that Gateway loads the new agent.

Homebrew on macOS and Linux:

```sh
brew install racetozero/tap/ibkit
```

Homebrew owns that binary, so update it with `brew upgrade racetozero/tap/ibkit` instead of `ibkit update`.

## Build and run

Use stable Rust 1.89 or newer. Supported hosts are Linux amd64, Linux arm64, and macOS Apple Silicon; Windows x64 is experimental (see [Windows](#windows-experimental)). Use the English Gateway UI.

```sh
cargo build --release -p ibkit-cli
cp crates/ibkit-gateway/config.example.toml config.toml
```

Two paths tell the controller what to run:

- `executable`, the **Gateway launcher**: the program that starts IB Gateway. When you leave it unset, the controller and the TUI use the newest Gateway that IBKR's installer put in `~/Applications/IB Gateway <version>/` (macOS, also `/Applications`) or `~/Jts/ibgateway/<version>/` (Linux). On macOS the launcher is the app's `Contents/MacOS/JavaApplicationStub`.
- `agent`, the **native agent**: this project's automation library, `libibkit_gateway_agent.dylib` (macOS) or `libibkit_gateway_agent.so` (Linux), built with the command above. The controller loads it into Gateway's Java process (`-agentpath`). Inside Gateway it fills in the login, enters TOTP codes, answers dialogs, sets the API settings, and reports Gateway's state to the controller. When you leave it unset, the controller uses the one next to the `ibkit` binary (or in `../lib`, or `/usr/local/lib`).

`ibkit gateway config` shows the paths that it found. Set them only for another location. On a local desktop, set `manage_display = false`. Linux servers can set it to `true` to start a private Xvfb display.

Supply `IB_USERNAME` and `IB_PASSWORD` through the environment, or set `username_file` and `password_file` to private UTF-8 files. Credential files can have one final line break. Spaces within the credential are preserved. Do not put credential values in TOML or command arguments.

```sh
target/release/ibkit gateway --config config.toml validate --credentials
target/release/ibkit gateway --config config.toml run
```

The config file is optional. Every key is also a flag (`--api-port 4001`) and an `IBKIT_*` variable (`IBKIT_API_PORT=4001`). Precedence, lowest first: defaults, the config file (`--config`, `IBKIT_CONFIG`, or `./config.toml` when it exists), settings saved through the control API (`state_dir/api-settings.toml`), variables, flags. `ibkit gateway config` prints the effective settings; `ibkit gateway --help` lists every flag.

```sh
ibkit gateway run --executable /opt/ibgateway/ibgateway --agent /usr/local/lib/libibkit_gateway_agent.so \
  --state-dir /var/lib/ibkit/state --settings-dir /var/lib/ibkit/settings --trading-mode paper
```

`run` stays in the foreground and writes JSON events to standard output. Approve the IB Key request on your phone. The default mode is paper trading on port 4002. Set both `trading_mode = "live"` and the intended API port for live use.

The default API and warning settings match IBAutomater: API write access, API logs, order precaution bypass, and warning acceptance are enabled. Use `read_only_api`, `bypass_order_precautions`, and `accept_order_warnings` to select your policy. The default existing-session policy is `refuse`.

Set `auto_login = false` to inspect the login screen or enter credentials manually. This mode does not need credential sources. It does not press a login button.

## Windows (experimental)

The controller, the native agent (`ibkit_gateway_agent.dll`) and the TUI build for Windows x64, and CI runs the Windows platform tests. They have not yet run against a real Gateway on Windows; report what you find.

- Gateway is found in `C:\Jts\ibgateway\<version>\ibgateway.exe` (IBKR's default; also `%USERPROFILE%\Jts`), the agent next to `ibkit.exe`. Do not copy `config.example.toml`: it holds the container paths and `manage_display = true`, which Windows refuses. Run `ibkit gateway tui`, or `ibkit gateway run` with only the settings you need.
- Each session runs in a Job Object named after its session ID. The launcher enters it before it runs, so `stop` and crash detection cover every Gateway process, also the restart child. Gateway outlives the controller, and a new controller adopts it.
- Ctrl-C and Ctrl-Break stop Gateway and end the controller. Closing the console window, logging off or shutting down ends the controller at once and leaves Gateway running for the next controller, because Windows allows only a few seconds there.
- Windows has no file modes: the state directory's access list keeps credentials and status private. Keep `state_dir` under your user profile.
- `manage_display` and `vnc_listen` are Linux features; Gateway uses the Windows desktop.

A first check on a Windows machine with Gateway installed: `ibkit gateway config` (it shows the paths it found), then `ibkit gateway run --auto-login false` (the Gateway login screen opens), `ibkit gateway status` in a second console (state `starting`, a `process_group`), and `ibkit gateway stop` (Gateway closes within `shutdown_timeout_secs`).

## Terminal workspace

Use the TUI to enter credentials and change settings without editing TOML by hand:

```sh
target/release/ibkit gateway tui
target/release/ibkit gateway --config /private/path/config.toml tui
```

The workspace has two views. **Settings** lists the sections on the left, the fields of one section in the middle, and help, the config key and validation results for the selected field on the right (below on narrow terminals). A section with an invalid value has a `!`. Values are edited in place. **Overview** shows the session (state, time in that state, API address, recovery countdown, the last error and what to do next) above the event log. Starting Gateway opens the Overview. The header always shows the session state and PAPER or LIVE.

The event log keeps 2000 entries, also across runs in one workspace. It follows new events until you scroll up, then stays on the selected event while new events arrive. Identical consecutive lines are kept once with a count. Enter shows the selected event in full with the raw controller event, which you can select and copy with the mouse.

The TUI opens a new config with defaults or loads an existing one. It uses the same config keys and validator as the headless commands. Paths remain relative to the working directory. Invalid TOML is preserved and reported; it is not replaced with defaults.

| Key | Action |
| --- | --- |
| Tab, `1`, `2` | Change view: Overview, Settings |
| `?` | Show every key |
| `r` / `x` | Start / stop Gateway |
| `c` / `t` | Restart with a new login / soft restart |
| `n` / `l` | Reconnect the account / export Gateway logs |
| `s` | Validate and save settings |
| q / Esc | Close the workspace; confirm discarding edits or stopping an active run |
| Ctrl-C | Stop the owned run and close the workspace |
| **Settings** | |
| Up / Down (`k` / `j`) | Select a field |
| Left / Right | Change section: Login, Gateway, API, Control, Recovery, Schedule |
| Enter / Space | Edit a field or cycle a choice |
| Enter / Esc while editing | Apply or cancel the edit |
| Left / Right, Home / End, Ctrl-U while editing | Move the cursor or clear the value |
| **Event log** | |
| Up / Down (`k` / `j`), PgUp / PgDn, Home / End (`g` / `G`) | Select an event; End follows new events again |
| Enter | Show the selected event in full |
| `/` | Filter by text; Enter keeps the filter |
| `e` | Show only warnings and errors |
| Esc | Clear the filter |

Letter shortcuts apply in the workspace. In a field editor, letters enter text; Enter applies the edit and Esc cancels it.

Both username and password are masked, including during paste. Enter both fields, or leave both empty to use the configured credential files or environment sources. Input accepts one line, up to 4096 UTF-8 bytes. The TUI does not display credentials already stored in files or environment variables. IB Key approval still takes place on your phone.

By default, entered credentials are used only for the current run. Private temporary files keep them available to Gateway's daily restart children, then are removed after shutdown. `s` saves settings without credential values. To retain entered credentials for later runs, turn on **Save credentials**, then press `s`. Credentials are stored as plaintext in files with mode 0600 inside a mode 0700 directory beside the config; TOML stores only their paths. Unchanged credentials reuse their files. When credentials change, the old private directory is retained so an existing session cannot lose access; remove obsolete directories only after their sessions stop. This is file storage, not an operating-system keychain.

`r` validates the current draft and starts the normal controller with a private config snapshot. It does not require `s` first. Live mode requires explicit confirmation. Edits and saves during a run apply to the next Stop/Start; `c` and `t` use the active run's original settings. The header names the next-start mode and the session pane names the active mode. A second Start cannot create another controller for that workspace.

The TUI owns the controller subprocess and closes its session on exit. If forced cleanup cannot confirm process ownership, it reports the problem and retains the private session files for manual cleanup. It does not declare that unknown processes have stopped. Config-file commands, Docker, and Helm remain available. The TUI needs an interactive terminal of at least 76 columns by 22 rows. It does not provide a remote desktop for Gateway account tasks.

## Control

Use the same config file and state directory for each command:

```sh
ibkit gateway status
ibkit gateway health --kind live
ibkit gateway health --kind ready
ibkit gateway export-logs
ibkit gateway reconnect-account
ibkit gateway reconnect-data
ibkit gateway soft-restart
ibkit gateway restart
ibkit gateway reload
ibkit gateway pause
ibkit gateway stop
ibkit gateway reset-recovery
```

`reload` (or SIGHUP) reads the settings again. It starts a new session only when a setting that Gateway reads changed; controller settings (alerts, recovery, probes, forwarder, schedule) apply at once. `state_dir` cannot change while the controller runs. `pause` stops Gateway and keeps the controller up, also across its own restarts, until `restart`. `soft-restart` is refused before Gateway is ready. `validate --files` also checks that the launcher and agent exist; `validate --credentials` reads the credential and TOTP sources.

Commands go to a queue in `state_dir/control/` and run in the order sent, one per controller step (500 ms). A command applies to the controller that was running when it was sent, also after a reload or restart starts a new session; a replacement controller drops it. Reloads in a row run once.

`reconnect-account` and `reconnect-data` send Gateway's reconnect shortcuts (menu-shortcut key + Alt + R or F, IBC's RECONNECTACCOUNT and RECONNECTDATA) to a ready session. They reconnect without a new login. `restart` starts a new authenticated session. `soft-restart` sets Gateway's own restart time to two minutes from now. The new JVM restores the configured daily time. The default daily time is 23:45 in the system time zone. A soft restart is limited to three requests per hour. It has a separate timeout.

The controller follows restart children through session-tagged agent reports. It emits `restarted` when a new process completes configuration. The native agent checks Gateway's `restart` property and does not enter credentials during token restoration. A token-expiry dialog produces an AuthenticationRequired result. Automatic recovery is on by default: transient faults get a cold start with a delay that doubles from 60 s up to 30 minutes, without an attempt limit (`recovery_attempts = 0`). Faults that a retry cannot fix (wrong password, account tasks, unsupported second factor) halt the controller: Gateway stops, the state is `halted`, the controller stays up (`health --kind live` passes, `ready` fails), and it logs in again only after `restart` (or `reload`). `failed` is the state of one failed session that recovery may retry. A replacement controller takes over a Gateway that is still running, without a new login.

`health --kind live` checks the controller heartbeat. `health --kind ready` also requires completed UI configuration and a valid framed IB API greeting. An open TCP port alone does not pass. Health checks do not submit orders or reserve a client ID.

## Control API

Set `control_listen` (for example `127.0.0.1:5800`) and a bearer token of at least 16 characters in `IBKIT_CONTROL_TOKEN` (or `control_token_file`) to serve a REST and WebSocket API from `run`:

| Method and path | Token | Purpose |
| --- | --- | --- |
| `GET /v1/health`, `GET /v1/health/ready` | no | Liveness and readiness (200 or 503) |
| `GET /v1/status` | yes | Controller status, agents, recovery phase |
| `POST /v1/control` `{"control": "restart"}` | yes | `stop`, `restart`, `soft_restart`, `export_logs`, `reconnect_account`, `reconnect_data`, `reload`, `pause` |
| `GET /v1/config`, `PATCH /v1/config`, `DELETE /v1/config` | yes | Effective settings; change keys (`null` removes an API value); remove all API values |
| `PUT /v1/credentials` `{"username", "password"}` | yes | Save the login in private files in `state_dir/credentials` |
| `PUT /v1/totp` `{"secret"}`, `DELETE /v1/totp` | yes | Save or remove the Mobile Authenticator secret |
| `GET /v1/events` (WebSocket) | yes | Controller events as JSON text messages |
| `GET /v1/metrics` | yes | Prometheus text metrics |
| `GET /v1/openapi.json` | no | The OpenAPI 3.1 document of this API |

The API refuses `state_dir`, keys that a flag or variable sets, and keys that choose the programs that run, the credential sources, VNC or the API itself (403). Live trading, remote or writable API access, accepted incoming connections, bypassed precautions and `api_listen` need `control_api_full_access = true`, which only the file, flags and variables can set. Settings saved through the API take precedence over the file; the controller lists them at start, and `DELETE /v1/config` removes them. It has no TLS: keep it on loopback or a private network, or terminate TLS in a proxy in front of it. Clients: `ibkit-gateway-client` (Rust), `ibkit.gateway.GatewayClient` (Python), `@ibkit/node/gateway` (TypeScript; plain `fetch`, no native addon). The Python and TypeScript types (states, error codes, events as tagged unions, the settings) are generated from [`openapi.json`](openapi.json) by `scripts/gen_gateway_types.py` (`just openapi` runs both steps; CI fails when a file is stale). For other languages, generate a client from the same document (`ibkit gateway openapi` prints it).

### Metrics

`GET /v1/metrics` uses the bearer token (Prometheus `authorization` with type `Bearer`; the Helm chart makes a ServiceMonitor with `controlApi.serviceMonitor.enabled`). It has:

- `ibkit_gateway_up`, `ibkit_gateway_ready`, `ibkit_gateway_state{state}`, `ibkit_gateway_status_age_seconds`
- `ibkit_gateway_recovery_phase{phase}` (`blocked` waits for an operator) and `ibkit_gateway_recovery_retry_time_seconds`
- `ibkit_gateway_agent_heartbeat_age_seconds{pid}` and `ibkit_gateway_jvm_max_heap_bytes{pid}`
- `ibkit_gateway_last_ready_time_seconds`, `ibkit_gateway_controller_start_time_seconds`
- counters: `ibkit_gateway_gateway_launches_total`, `ibkit_gateway_errors_total{code}`, `ibkit_gateway_recoveries_scheduled_total`, `ibkit_gateway_gateway_restarts_total`, `ibkit_gateway_api_unavailable_total`, `ibkit_gateway_halts_total`, `ibkit_gateway_alerts_sent_total`, `ibkit_gateway_alerts_failed_total`, `ibkit_gateway_events_dropped_total`

Useful alert rules: `ibkit_gateway_recovery_phase{phase="blocked"} == 1` (needs you), `ibkit_gateway_ready == 0` for longer than your longest expected recovery, and `time() - ibkit_gateway_last_ready_time_seconds` with `ibkit_gateway_ready == 0`.

### Alerts

Set `alert_webhook_url` (or `IBKIT_ALERT_WEBHOOK_URL`) to receive a JSON POST when:

| `alert` | When |
| --- | --- |
| `down` | A login or a running Gateway failed (once until Gateway is ready again) |
| `recovered` | Gateway is logged in again after `down`, `halted` or `exhausted` |
| `halted` | A fault that a new login cannot repair (wrong password, account tasks): correct it and send `restart` |
| `exhausted` | The hourly `recovery_attempts` budget is used up; recovery continues when it permits |
| `controller_failed` | The controller itself stopped with an error |

The body is `{"alert", "text", "at", "session", "state", "reason", "message"}` (the `Alert` schema in the OpenAPI document). Slack and Mattermost incoming webhooks show `text`. A failed delivery is retried after 2, 10 and 30 seconds and never stops the controller. `GET /v1/config` shows the URL to token holders.

```sh
curl -H "Authorization: Bearer $IBKIT_CONTROL_TOKEN" http://127.0.0.1:5800/v1/status
curl -X POST -H "Authorization: Bearer $IBKIT_CONTROL_TOKEN" -d '{"control":"reconnect_account"}' \
  -H 'Content-Type: application/json' http://127.0.0.1:5800/v1/control
```

## Library

```rust,no_run
use ibkit_gateway::{Config, Gateway};

# async fn example() -> anyhow::Result<()> {
let config = Config::load(std::path::Path::new("config.toml"))?;
let mut gateway = Gateway::new(config)?;
let mut events = gateway.events().subscribe();
let result = gateway.start().await?;
if result.has_error() {
    gateway.stop().await?;
    anyhow::bail!("{}", result.error_message);
}
// Call gateway.poll().await regularly to track restarts and deliver events.
gateway.stop().await?;
# Ok(())
# }
```

The library also provides `launch`, `poll`, `restart`, `soft_restart`, `export_logs`, `is_running`, `is_authenticating`, `last_start_result`, and a bounded event subscription. Maintenance queries are in `ibkit_gateway::schedule`. Use `Region::from_peer` with the `Peer` value in Gateway's `jts.ini`.

For an unattended controller, use `resume`, `poll_recovery`, and `recover` with one `Recovery` value. Managed startup saves retry state in the private state directory and resumes it after controller replacement. Keep that directory on persistent storage. `reset-recovery` requires a stopped controller and operator review of the failure. Manual `start` and `launch` calls do not load the automatic budget.

`ibkit_gateway::client` provides connection-generation checks, subscription restoration tracking, snapshot end-marker checks, and permanent-order-ID presence checks. The trading client must feed its own callbacks and durable intent ledger. It must still check quantities, cancellations, execution corrections, prices, and risk limits.

## Docker

```sh
docker build --target runtime -t ibkit-rs:0.1.0 .
docker volume create ibkit-state
docker run -d --name ibkit --restart unless-stopped \
  --env-file /secure/ibkit.env \
  -v ibkit-state:/var/lib/ibkit \
  -p 127.0.0.1:4002:4004 --stop-timeout 45 ibkit-rs:0.1.0
docker logs -f ibkit
```

Every setting can come from the environment instead of the file, for example `-e IBKIT_TRADING_MODE=live -e IBKIT_API_PORT=4001`. To enable the control API, add `-e IBKIT_CONTROL_LISTEN=0.0.0.0:5800 -e IBKIT_CONTROL_TOKEN=<random>` and `-p 127.0.0.1:5800:5800`. `--restart unless-stopped` is safe: a fault that needs an operator is saved and halts the controller, so a restarted container does not log in again until it gets `restart`. To take Gateway down for a while, send `pause`: `stop` ends the controller, and the restart policy starts it again.

Publish the API port on loopback (`-p 127.0.0.1:...`) or a private network. Gateway sees every client of the forwarder as 127.0.0.1, so its trusted-IP setting does not limit them; `api_allowed_sources` limits the forwarder's sources (behind Docker port publishing the source can be the bridge address). For account tasks or an unknown dialog, mount a password file and set `-e IBKIT_VNC_LISTEN=0.0.0.0:5900 -e IBKIT_VNC_PASSWORD_FILE=/run/secrets/vnc -p 127.0.0.1:5900:5900`, then connect a VNC viewer to the host's loopback (through an SSH tunnel from elsewhere). The Helm chart has `vnc.enabled` with `kubectl port-forward`.

Keep the stop timeout above `shutdown_timeout_secs` (30 s by default); with Compose, set `stop_grace_period: 45s`. On stop the controller closes Gateway's main window, which logs out of IBKR. Docker's default of 10 s kills Gateway first, and IBKR can then hold the user's session for a long time, so that the next login is not answered.

BuildKit selects the matching vendor installer for amd64 or arm64. Rust builds use the build host and a cross compiler when needed. Gateway still uses the target CPU. To build both images:

```sh
docker buildx build --platform linux/amd64,linux/arm64 --target runtime \
  -t registry.example/ibkit-rs:0.1.0 --push .
```

`GATEWAY_CHANNEL` accepts `latest` or `stable`. Supply `--build-arg GATEWAY_SHA256=<expected-hash>` to check a vendor installer. The image records the downloaded hash at `/opt/ibgateway/installer.sha256`. The vendor's latest URL can change; record and check the hash for repeatable deployments.

The image runs as UID 10001, starts Xvfb through the Rust controller, and uses tini to deliver signals and collect child processes. It stores settings and private logs under `/var/lib/ibkit`. No desktop port is exposed. A Rust forwarder carries container port 4004 to Gateway's loopback API port 4002. Gateway can retain local-only API access. Protect the published port as you would the trading API itself. The forwarder adds no authentication or encryption.

## Kubernetes

Create a Secret from two private files. The chart does not create or embed credentials:

```sh
kubectl create secret generic ibkit-credentials \
  --from-file=username=/secure/username --from-file=password=/secure/password
helm upgrade --install trading charts/ibkit-gateway \
  --set image.repository=registry.example/ibkit-rs
```

The chart uses one replica, a Recreate update, a PVC, non-root permissions, a Secret volume, and separate live and ready probes. Its Service forwards the API port to the Rust loopback forwarder. A NetworkPolicy denies inbound traffic by default. Set `networkPolicy.ingress` to allow the intended client pods. Gateway's default incoming-connection policy is manual; `accept` and `reject` are explicit options. The chart does not expose the API to the public internet.

Set `controlApi.enabled=true` and `controlApi.existingSecret` (a Secret with key `token`) to serve the control API on port 5800 of the Service. The liveness probe passes while the controller is halted, so Kubernetes does not restart a pod that waits for an operator; readiness fails until Gateway is logged in.

Set `persistence.existingClaim` to use an existing volume. Set `persistence.enabled=false` only when persistent settings and restart tokens are not needed. A pod replacement is a cold start; it is not a Gateway daily soft restart.

```sh
cargo fmt --all -- --check

```

Install the prebuilt cargo-nextest tool before running these checks. The JVM check needs a desktop display or `xvfb-run -a`. It uses an independent Swing test application and checks paper login, IB Key, modal UI access, settings, warning acceptance, export, restart, takeover, incoming connections, and shutdown confirmation. Failure scenarios include repeated mobile prompts, rejected sessions, account tasks, security cards, unknown dialogs, stalled re-login, and token expiry. The ordinary nextest profile excludes the JVM binary. JVM tests are explicitly ignored by plain cargo test; they never count missing prerequisites as success.

## Logs and limits

State directories are private. Event logs exclude credential text fields and redact both credentials. Credential files take precedence over their configured environment variables; remove stale environment values when rotating secrets. The native event log rotates at 10 MiB. Raw Gateway and launcher logs remain private on disk; they are not copied into the public event stream. `launcher-stdio.log` can explain a launcher failure before the agent starts.

Use a separate state and settings directory for each account. An exclusive file lock rejects a second controller for the same state directory. Shutdown targets owned processes and current session reports. It does not use `pkill java` or `pkill Xvfb`.

Second factor: IB Key waits for approval on the phone. With the Mobile Authenticator (TOTP) secret in `totp_secret_env` (default `IB_TOTP_SECRET`) or `totp_secret_file`, the agent selects that method and enters the current code; it never reuses a code. The secret then sits beside the password, so whoever controls the host has both factors; use a file or Secret on a host only you control. A passkey prompt fails unless `passkey_authenticate = true`, which only presses Authenticate; an authenticator beside Gateway must complete it. Enable one second-factor method for the user: Gateway preselects one, and switching can end the session. Security cards and account tasks require manual action.

Unknown dialogs are never clicked. Gateway's generic "Gateway" dialog can be its login progress indicator, where OK cancels the login. An unknown modal dialog that still blocks authentication after `unknown_dialog_timeout_secs` (120 s) produces UnknownMessageWindowDetected. When IBKR does not answer two login requests (`AuthTimeoutMonitor-CCP: Timeout!` in `launcher.log`), the agent reports AuthenticationNotAnswered: usually another session holds the user's slot. This result does not retry automatically, because another login would be dropped the same way. The library does not retry rejected credentials forever or choose a weekend retry time for the caller.
